## 关键指令——请首先阅读

使用 Python/openpyxl。编写公式字符串（`ws["D20"] = "=B5*B6"`），然后在交付前运行 `excel-author` 技能的 `recalc.py` 辅助脚本。

### 核心原则
*   **每个计算都必须是 Excel 公式**——**绝不**在 Python 中计算值并将结果硬编码到单元格中。使用 openpyxl 时，编写 `cell.value = "=B5*B6"`（公式字符串），而不是 `cell.value = 1250`（计算结果）。模型必须是动态的，并在输入更改时更新。
*   **使用模板结构**——遵循 `examples/LBO_Model.xlsx` 或用户提供的模板中的组织结构。不要发明自己的布局。
*   **使用正确的单元格引用**——所有公式都应引用相应的单元格。绝不键入应来自其他单元格的数字。
*   **保持符号约定的一致性**——遵循模板使用的任何符号约定（有些使用负号表示流出，有些使用正号）。在整个过程中保持一致。
*   **按部分工作，在每个步骤与用户验证**——完整完成一个部分，向用户展示构建的内容，运行该部分的验证检查，并在**继续下一部分之前**获得确认。不要从头到尾构建整个模型然后才呈现——后面的部分依赖于前面的部分，因此，在回报部分已经构建好之后才发现资金来源与运用部分的错误，意味着所有地方都需要返工。

### 公式颜色约定
*   **蓝色 (0000FF)**：硬编码输入——不引用其他单元格的键入数字
*   **黑色 (000000)**：包含计算的公式——任何使用运算符或函数的公式（`=B4*B5`、`=SUM()`、`=-MAX(0,B4)`）
*   **紫色 (800080)**：指向**同一工作表**上单元格的链接——没有计算的直接引用（`=B9`、`=B45`）
*   **绿色 (008000)**：指向**不同工作表**上单元格的链接——跨工作表引用（`=Assumptions!B5`、`='Operating Model'!C10`）

### 填充颜色调色板——专业的蓝色和灰色（默认，除非用户/模板另有规定）
*   **保持简洁**——仅使用蓝色和灰色进行单元格填充。**不要**引入绿色、黄色、红色或多种强调色。专业的 LBO 模型需要克制。
*   **默认填充调色板：**
    *   **部分标题**（资金来源与运用、运营模型等）：深蓝色 `#1F4E79`，白色粗体文本
    *   **列标题**（第 1 年、第 2 年等）：浅蓝色 `#D9E1F2`，黑色粗体文本
    *   **输入单元格**：浅灰色 `#F2F2F2`（或仅白色）——蓝色*字体*是信号，填充是次要的
    *   **公式/计算单元格**：白色，无填充
    *   **关键输出**（IRR、MOIC、退出权益）：中蓝色 `#BDD7EE`，黑色粗体文本
*   **这就是整个调色板。** 3 种蓝色 + 1 种灰色 + 白色。如果模板使用自己的颜色，请遵循模板。
*   注意：上述蓝色/黑色/紫色/绿色**字体**颜色用于区分输入、公式和链接。这些与这里的**填充**调色板是分开的——两者协同工作。

### 数字格式标准
*   **货币**：`$#,##0;($#,##0);"-"` 或 `$#,##0.0`，取决于模板
*   **百分比**：`0.0%`（一位小数）
*   **倍数**：`0.0"x"`（一位小数）
*   **MOIC/详细比率**：`0.00"x"`（两位小数以提高精度）
*   **所有数字单元格**：右对齐

## 模板分析阶段 - 首先执行此操作

在填写任何公式之前，彻底检查模板：

1. **映射结构** - 识别每个部分的位置以及它们之间的关系。注意哪些部分为其他部分提供数据。

2. **理解时间线** - 哪些列代表哪些期间？是否有"期末"或"备考"列？预测期从何处开始？

3. **区分输入单元格与公式单元格** - 模板通常使用颜色编码、边框或阴影来指示哪些单元格需要输入，哪些需要公式。请遵循这些惯例。

4. **仔细阅读现有标签** - 行标签准确地告诉你预期的计算是什么。不要假设 - 阅读模板要求的内容。

5. **检查现有公式** - 有些模板已部分填充。除非特别要求，否则不要覆盖有效的公式。

6. **注意模板特定的惯例** - 符号惯例、小计结构、各部分如何组织、是否为不同组件设置了单独的工作表标签等。

## 常见问题领域

以下计算模式在 LBO 模型中经常引起问题。遇到这些情况时请特别注意：

### 平衡部分
* 当两个部分必须相等时（例如，资金来源 = 资金运用），通常有一项是"平衡项"
* 识别哪一项是平衡项，并将其计算为差额

### 税务计算
* 税务公式应仅引用相关的收入项目和税率
* **不应**引用不相关的部分（例如，债务计划表）
* 考虑亏损是否产生税盾或是否被忽略

### 利息和循环引用
* 如果利息计算引用了受现金流影响的余额，则可能产生循环引用
* 使用**期初余额**（而非平均或期末余额）来打破循环引用
* 模式：利息 → 现金流 → 偿还 → 期末余额（如果利息使用期末余额，则会循环回来）

### 债务偿还 / 现金扫除
* 当存在多个债务层级时，通常有优先顺序
* 现金扫除应遵循优先偿还顺序
* 余额不能为负 - 适当地使用 MAX 或 MIN 函数

### 回报计算（IRR/MOIC）
* 现金流必须有正确的符号：投资 = 负，收益 = 正
* 如果使用 XIRR，需要相应的日期
* 如果使用 IRR，现金流应处于连续期间
* MOIC = 总收益 / 总投资

### 敏感性分析表
* **使用奇数维度**（5×5 或 7×7）— 切勿使用 4×4 或 6×6。奇数维度确保存在真正的中心单元格。
* **中心单元格 = 基准情况。** 围绕模型的实际假设对称地构建行和列轴值（例如，如果基准进入倍数为 10.0x，则轴 = `[8.0x, 9.0x, 10.0x, 11.0x, 12.0x]`）。中心单元格的 IRR/MOIC 必须等于模型的实际 IRR/MOIC 输出 — 这是证明表格连接正确的证据。
* **突出显示中心单元格** — 使用中等蓝色填充（`#BDD7EE`）+ 粗体字体，以便基准情况在视觉上得到锚定。
* Excel 的 DATA TABLE 函数可能无法与 openpyxl 配合使用 — 应编写显式引用行/列标题的公式
* 每个单元格应显示**不同的**值 — 如果全部相同，则公式没有正确变化
* 使用混合引用（例如，行输入用 `$A5`，列输入用 `B$4`）

## 验证清单 - 完成后运行

### 运行公式验证
```bash
python /path/to/excel-author/scripts/recalc.py model.xlsx
```
必须返回成功且零错误。

### 部分平衡
- [ ] 任何必须平衡的部分（资金来源/运用、资产/负债）都完全平衡
- [ ] 平衡项作为平衡数字计算正确
- [ ] 应在各部分之间匹配的金额保持一致

### 收入/运营预测
- [ ] 收入/顶线根据驱动因素或增长率正确构建
- [ ] 所有成本和费用项目计算适当
- [ ] 小计和总计求和正确
- [ ] 利润率和比率合理
- [ ] 与假设的链接正确

### 资产负债表（如适用）
- [ ] 资产 = 负债 + 权益（必须平衡）
- [ ] 所有项目都链接到适当的计划表或滚动预测
- [ ] 期初余额 = 上一期间期末余额
- [ ] 包含检查行并显示为零

### 现金流量表（如适用）
- [ ] 从正确的收入数字开始
- [ ] 非现金项目适当添加/减去
- [ ] 营运资本变动符号正确
- [ ] 期末现金 = 期初现金 + 净现金流
- [ ] 现金余额在各报表之间保持一致

### 支持性计划表
- [ ] 滚动预测计划表平衡（期初 + 变动 = 期末）
- [ ] 计划表正确链接到主报表
- [ ] 计算项目使用适当的驱动因素
- [ ] 所有期间的计算保持一致
### 债务/融资计划表（如适用）
- [ ] 期初余额与资金来源或上期数据勾稽
- [ ] 利息基于正确的余额计算（通常为期初余额）
- [ ] 还款金额考虑现金可用性和优先级
- [ ] 期末余额不能为负数
- [ ] 各分项总额加总正确

### 回报/输出分析
- [ ] 退出/终值计算正确
- [ ] 包含所有相关调整项
- [ ] 现金流符号正确（投资为负，收益为正）
- [ ] IRR/MOIC 公式引用完整的范围
- [ ] 结果在给定情景下合理

### 敏感性分析表（如适用）
- [ ] 网格维度为奇数（5×5 或 7×7）——存在一个真正的中心单元格
- [ ] 行和列轴值围绕基准情况对称（`[基准-2Δ, 基准-Δ, 基准, 基准+Δ, 基准+2Δ]`）
- [ ] 中心单元格输出等于模型的实际 IRR/MOIC——确认表格链接正确
- [ ] 中心单元格高亮显示（填充中蓝色 `#BDD7EE`，字体加粗）
- [ ] 行标题和列标题包含适当的输入值
- [ ] 每个数据单元格包含公式（非硬编码）
- [ ] 每个数据单元格显示不同的值
- [ ] 数值按预期方向变动（更高的退出倍数 → 更高的 IRR，等等）

### 格式
- [ ] 硬编码输入为蓝色（0000FF）
- [ ] 计算公式为黑色（000000）
- [ ] 同工作表链接为紫色（800080）
- [ ] 跨工作表链接为绿色（008000）
- [ ] 所有数字右对齐
- [ ] 全程应用适当的数字格式
- [ ] 没有单元格显示错误值（#REF!、#DIV/0!、#VALUE!、#NAME?）

### 逻辑合理性检查
- [ ] 数字数量级合理
- [ ] 趋势合理（增长、下降、稳定符合预期）
- [ ] 没有明显错误的值（应为正数处出现负数、不可能的百分比等）
- [ ] 关键输出值在分析类型的合理范围内

## 需避免的常见错误

| 错误 | 问题所在 | 如何修复 |
|-------|-----------------|------------|
| 硬编码计算值 | 输入变化时模型不更新 | 始终使用引用源单元格的公式 |
| 复制后单元格引用错误 | 公式指向错误的单元格 | 验证所有链接，使用适当的 `$` 锚定 |
| 循环引用错误 | 模型无法计算 | 利息类计算使用期初余额，打破循环 |
| 部分不平衡 | 应匹配的总额不匹配 | 确保有一项作为调节项（计算为差额） |
| 出现不可能的负余额 | 支付/使用超过可用金额 | 适当使用 `MAX(0, ...)` 或 `MIN` 函数 |
| IRR/回报错误 | 符号错误或范围不完整 | 检查现金流符号并确保公式覆盖所有期间 |
| 敏感性分析表显示相同值 | 公式未随输入变化 | 检查单元格引用——需要混合引用（`$A5`、`B$4`） |
| 滚动计算不勾稽 | 期初 ≠ 上期期末 | 验证各期间之间的链接 |
| 符号约定不一致 | 加法变成减法或反之 | 在整个模型中始终遵循模板的约定 |

## 与用户协作——分阶段检查点

*   **如果模板结构不清晰**，在继续之前询问
*   **如果用户需求与模板冲突**，确认用户的偏好
*   **完成每个主要部分后**，**停止**并在继续之前与用户验证：
    -   **资金来源与运用完成后** → 展示平衡的表格，确认调节项正确，在构建运营模型之前获得批准

*   **如果在验证过程中发现错误**，在进入下一部分之前修复它们
*   **展示你的工作**——在必要时解释关键公式或假设
*   **切勿在未进行每个部分检查的情况下呈现完整模型**——在源头发现错误的单元格引用比从损坏的 IRR 反向追溯要快得多
