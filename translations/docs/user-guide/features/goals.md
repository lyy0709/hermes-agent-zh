# 持久化目标 (`/goal`)

`/goal` 为 Hermes 设定一个跨回合持续存在的长期目标。每个回合结束后，一个轻量级的评判模型会检查助手的最后一次回复是否满足了目标。如果没有，Hermes 会自动将一个继续执行的提示词反馈到同一会话中并继续工作——直到目标达成、你暂停或清除了目标，或者回合预算耗尽。

这是我们对 **Ralph 循环** 的实现，直接受到 Eric Traut (OpenAI) 开发的 [Codex CLI 0.128.0 的 `/goal`](https://github.com/openai/codex) 启发。其核心思想——让目标在多个回合中保持活跃，不达目的不罢休——是他们的。这里的实现是独立的，并适配了 Hermes 的架构。

## 何时使用

当你希望 Hermes 自行迭代而无需你每回合都重新提示时，使用 `/goal`：

- “修复 `src/` 中的所有 lint 错误，并确保 `ruff check` 通过”
- “从仓库 Y 移植功能 X，包括测试，并使 CI 变绿”
- “调查会话 ID 为何有时在运行中压缩时发生漂移，并撰写报告”
- “构建一个根据 EXIF 日期重命名文件的小型 CLI，然后针对 photos/ 文件夹进行测试”

Agent 执行一个回合就停止的任务不需要 `/goal`。那些**否则你需要说三次‘继续’**的任务，才是这个功能大显身手的地方。

## 快速开始

```
/goal 修复 tests/hermes_cli/ 中所有失败的测试，并确保 scripts/run_tests.sh 在该目录下通过
```

你将看到：

1.  **目标已接受** — `⊙ 目标已设定 (20回合预算): <你的目标>`
2.  **第 1 回合运行** — Hermes 开始工作，就像你将目标作为普通消息发送一样。
3.  **评判模型运行** — 回合结束后，评判模型决定 `完成` 或 `继续`。
4.  **如果需要则触发循环** — 如果 `继续`，你会看到 `↻ 继续向目标前进 (1/20): <评判模型的理由>`，然后 Hermes 自动执行下一步。
5.  **终止** — 最终你会看到 `✓ 目标已达成: <理由>` 或 `⏸ 目标已暂停 — 已使用 N/20 回合`。

## 命令

| 命令 | 功能 |
|---|---|
| `/goal <文本>` | 设置（或替换）长期目标。立即启动第一个回合，因此你无需发送单独的消息。 |
| `/goal` 或 `/goal status` | 显示当前目标、其状态和已使用的回合数。 |
| `/goal pause` | 停止自动继续循环，但不清除目标。 |
| `/goal resume` | 恢复循环（将回合计数器重置为零）。 |
| `/goal clear` | 完全删除目标。 |

在 CLI 和所有消息网关平台（Telegram、Discord、Slack、Matrix、Signal、WhatsApp、SMS、iMessage、Webhook、API 服务器和 Web 仪表板）上的工作方式完全相同。

## 在目标执行中添加条件：`/subgoal`

当目标处于活动状态时，你可以使用 `/subgoal <文本>` 附加额外的验收条件，而无需重置循环。每次调用都会向目标的子目标列表中添加一个带编号的条目；Agent 在下一回合看到的**继续执行提示词**将包含原始目标加上一个“用户在循环中添加的额外条件”块，并且**评判提示词**会被重写，使得裁决必须考虑每个子目标——直到原始目标**和**每个子目标都满足时，目标才会被标记为完成。

| 命令 | 功能 |
|---|---|
| `/subgoal <文本>` | 向活动目标追加一个新条件。需要有一个活动的 `/goal`。 |
| `/subgoal` (无参数) | 显示当前带编号的子目标列表。 |
| `/subgoal remove <N>` | 删除第 N 个子目标（从 1 开始计数）。 |
| `/subgoal clear` | 删除所有子目标，但保持原始目标不变。 |

子目标与目标一起持久化存储在 `SessionDB.state_meta` 中，因此它们能在 `/resume` 后恢复。设置一个新的 `/goal <文本>` 会替换目标并清除子目标列表；`/goal clear` 也是如此。

当你启动一个循环（“修复失败的测试”）并在中途注意到你还希望它“为你刚刚修复的 bug 添加一个回归测试”时，可以使用此功能——`/subgoal 添加一个回归测试` 可以在不中断运行中循环的情况下收紧成功标准。

## 行为细节

### 评判模型

每个回合结束后，Hermes 会调用一个辅助模型，输入包括：

- 长期目标文本
- Agent 最近一次最终回复（最后约 4 KB 文本）
- 一个系统提示词，指示评判模型以严格的 JSON 格式回复：`{"done": <布尔值>, "reason": "<一句话的理由>"}`

评判模型被设计为保守：只有当回复**明确**确认目标已完成、最终交付物已清晰产出，或者目标无法实现/被阻塞时（视为完成并附带阻塞原因，这样我们就不会在不可能的任务上浪费预算），它才会将目标标记为 `完成`。

### 故障开放语义

如果评判模型出错（网络波动、响应格式错误、辅助客户端不可用），Hermes 会将裁决视为 `继续`——一个损坏的评判模型永远不会阻碍进展。**回合预算**是真正的最后保障。

### 回合预算

默认是 20 个继续回合（`config.yaml` 中的 `goals.max_turns`）。当预算用尽时，Hermes 会自动暂停，并明确告知你如何继续：

```
⏸ 目标已暂停 — 已使用 20/20 回合。使用 /goal resume 继续，或使用 /goal clear 停止。
```

`/goal resume` 会将计数器重置为零，因此你可以分阶段继续。

### 用户消息始终优先

当目标处于活动状态时，你发送的任何真实消息都优先于继续循环。在 CLI 上，你的消息会进入 `_pending_input`，排在排队的继续执行之前；在网关上，它同样通过适配器的 FIFO 队列。你的回合结束后评判模型会再次运行——所以如果你的消息恰好完成了目标，评判模型会捕捉到并停止。

### 运行中的安全性（网关）

当 Agent 已经在运行时，`/goal status`、`/goal pause` 和 `/goal clear` 可以安全运行——它们只影响控制平面状态，不会中断当前回合。在运行中设置**新**目标（`/goal <新文本>`）会被拒绝，并提示你先 `/stop`，这样旧的继续执行就不会与新的发生竞争。

### 持久化

目标状态存储在 `SessionDB.state_meta` 中，键为 `goal:<session_id>`。这意味着 `/resume` 会从你离开的地方继续——设定一个目标，关闭你的笔记本电脑，明天回来，`/resume`，目标仍然和你离开时完全一样（活动、暂停或完成）。

### 提示词缓存

继续执行提示词是一个附加到历史记录中的普通用户角色消息。它**不会**改变系统提示词、交换工具集或以任何使 Hermes 提示词缓存失效的方式触及对话。运行一个 20 回合的目标在缓存成本上与 20 回合的正常对话相同。

## 配置

添加到 `~/.hermes/config.yaml`：

```yaml
goals:
  # Hermes 自动暂停并要求你 /goal resume 之前的最大继续回合数。
  # 默认 20。如果你想要更紧凑的循环，可以降低此值；
  # 对于长时间运行的重构，可以提高此值。
  max_turns: 20
```

### 选择评判模型

评判模型使用 `goal_judge` 辅助任务。默认情况下，它解析到你的主模型（参见[辅助模型](/user-guide/configuration#auxiliary-models)）。如果你想将评判路由到一个廉价快速的模型以降低成本，可以添加一个覆盖配置：

```yaml
auxiliary:
  goal_judge:
    provider: openrouter
    model: google/gemini-3-flash-preview
```

评判调用很小（约 200 个输出 Token），每回合运行一次，因此一个廉价快速的模型通常是合适的选择。

## 示例演练

```
你: /goal 创建四个文件 /tmp/note_{1..4}.txt，每回合一个，每个文件包含其编号作为文本

  ⊙ 目标已设定 (20回合预算): 创建四个文件 /tmp/note_{1..4}.txt，每回合一个，每个文件包含其编号作为文本

Hermes: 现在创建 /tmp/note_1.txt。
  💻 echo "1" > /tmp/note_1.txt   (0.1s)
  我已创建 /tmp/note_1.txt，内容为 "1"。按照你的要求，我将在下一回合继续创建剩余的文件。

  ↻ 继续向目标前进 (1/20): 仅创建了 4 个文件中的 1 个；还有 3 个文件待创建。

Hermes: [继续向你的长期目标前进]
  💻 echo "2" > /tmp/note_2.txt   (0.1s)
  已创建 /tmp/note_2.txt。还有两个。

  ↻ 继续向目标前进 (2/20): 已创建 2/4 个文件；还剩 2 个。

Hermes: [继续向你的长期目标前进]
  💻 echo "3" > /tmp/note_3.txt   (0.1s)
  已创建 /tmp/note_3.txt。

  ↻ 继续向目标前进 (3/20): 已创建 3/4 个文件；还剩 1 个。

Hermes: [继续向你的长期目标前进]
  💻 echo "4" > /tmp/note_4.txt   (0.1s)
  所有四个文件都已创建：/tmp/note_1.txt 到 /tmp/note_4.txt，每个文件包含其编号。

  ✓ 目标已达成: 所有四个文件都已创建并包含指定内容，目标完成。

你: _
```

四个回合，一次 `/goal` 调用，你零次“继续”提示。

## 当评判模型出错时

没有评判模型是完美的。需要注意两种故障模式：

**假阴性 — 评判模型说继续，但目标实际上已完成。** 回合预算会捕捉到这种情况。你会看到 `⏸ 目标已暂停`，然后可以 `/goal clear` 或直接发送新消息。

**假阳性 — 评判模型说完成，但工作仍有剩余。** 你会看到 `✓ 目标已达成`，但你知道并非如此。发送后续消息以继续，或者更精确地重新设定目标：`/goal <更具体的文本>`。评判模型的系统提示词被故意设计得保守，以使假阳性比假阴性更少见。

如果你觉得评判裁决不可信，`↻ 继续向目标前进` 或 `✓ 目标已达成` 行中的理由文本会明确告诉你评判模型看到了什么。这通常足以诊断是目标文本模糊还是模型的响应有问题。
